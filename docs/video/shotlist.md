# Crosswalk demo video: shot list

File `crosswalk-demo.mp4` (v4, uploaded separately, not committed): 1920x1080, 30 fps, 3:14.3 (194.3 s), H.264 + AAC 48 kHz, loudness normalised to -14 LUFS. Captions are burned in and also provided as [`crosswalk-demo.srt`](crosswalk-demo.srt); the spoken text is in [`narration.md`](narration.md).

**What was recorded.** A headless browser captured the local stack on one PC on 25 October 2026: the Crosswalk UI and agent server (a separate server process on its own port, over a scratch copy of the data directory, so the runs on camera did not touch the repository's saved runs), the Zetaris gateway, Zetaris Lightning in Docker and Nemotron 3 Nano 4B in Ollama. Two questions were asked on camera through the UI and ran end to end with the model: the demo question cold (run `r20261025T1832399e97`) and the same question for Q1 2023 warm (run `r20261025T183917676f`). The screenshots were taken while the model ran, on the same machine.

**Before recording** the GHCN-Daily 2022 and 2023 TMAX and TMIN views were registered in Zetaris through the same `register_source` endpoint the agent uses (four operator calls, 53.6 to 54.4 s each), meant to give the Q1 2023 answer its weather. The warm run did not use them: the agent's set of registered objects is its manifest plus the registrations it made itself (its source_access memories), and these four were made outside a run, so the Q1 2023 answer on camera lists weather as not tested. The FEMA Q1 2023 declarations and the Q1 2022 revenue frames were left unregistered before recording: the warm run registers them live on camera.

**Footer numbers.** The two runs on camera are not runs of the evaluation, so their footers differ from the evaluation card: the cold run took 290.8 s at a median 140.3 tok/s and the warm run 197.3 s at 141.2 tok/s, against 247.7 to 285.8 s for the evaluation's cold runs with the model and 132.9 / 133.1 tok/s in its ablation (`docs/eval-report.md`). The cause of the tok/s difference is not measured.

**v4 (25 October 2026), a re-cut of v3 from the same takes.** v3 was 3:28.6. Changes:

- The 69 s of discovery timeline in v3 (0:33.5 to 1:42), mostly fast time-lapses of small log rows, is replaced by the 1.5x search-and-probe beat (unchanged) and three held frames of the same live take with callouts: the SEC company number padded to ten digits (97.7%, IDACORP the orphan), the FEMA state key (87.5%, PARTIAL, Alaska the orphan) beside the FEMA FIPS key (100%, VERIFIED), and the unpadded control (0.0%, REJECTED). The red "reply invalid" rows are labelled on screen as the guard catching an invalid model reply: after two invalid replies the model's step is not used and the host runs the next checklist step itself. Each held frame carries the badge "held frame, callout added"; the rows in the callouts are enlarged copies of the captured rows, not retyped.
- The FEMA callout says what the answer gate added after this recording checks: FEMA's state codes join the state reference (the FIPS key); the state key measures coverage (7 of 8 declared states have a seed utility) and is reported, not gated, unless the state join returns no rows.
- The provenance drawer is re-shot on a cell whose own rows the saved run kept (Evergy's degree-day change, +22.89%: 2 of the statement's 28 rows feed it, and both were kept), so it opens without v3's "cannot be fully recomputed" warning. It was captured after recording from the same saved cold run, reopened in the UI of the public code on a local server over a copy of the data directory (label bar: "Saved run"; the UI shows its REPLAY banner); the same style rule hides the SEC revenue levels.
- The evaluation card now comes before the architecture recap, and is shown with camera moves (model against baseline, then the hand baseline) instead of a 17 s static hold; the video ends on the answer card and a closing card.
- v3's closing line ("Every key measured before anything uses it") and the compile_usl line are cut. One new line closes the video (see `narration.md`); every other line is the v3 take.

**Label bar.** "LIVE" marks footage while the run streams (the UI shows its own LIVE banner); held frames of that footage add the badge "held frame, callout added". When a run finishes, the UI switches its banner to REPLAY (the run is now saved); from that frame on the bar says "Same take: the run has finished" and never LIVE, so no frame carries both. The drawer shot says "Saved run". The Ask screen has no UI banner and a neutral bar. Speed changes (8x to 30x on time-lapses, which carry no narration; 1.5x and 2.5x on the beats that do; 2.5x on the Zetaris UI) are labelled in the bar; 1x carries no badge.

**Edits in post:** the cuts, the held frames and their callouts, the camera windows (crops and eased zooms of the captured page or card), the speed changes and the label bar, and single frames caught mid-repaint while the page scrolled are replaced by the frame before them. During capture a pointer and a click ripple were drawn into the page, and one style rule hid the SEC revenue levels on the Answer screen (the repository publishes no SEC fact values; the year-on-year changes and tags stay visible). Nothing else was retouched and no text in a captured row was replaced. The Zetaris shots come from the Zetaris UI of the same instance; the login is not shown.

Still shots: the opening question card, the answer card (the 12 rows of `docs/eval-report.md` section 1), the title card, the repository's architecture diagram `docs/architecture.png`, an evaluation card (numbers from `docs/eval-report.md`, all measured) and a closing card with the data attributions and a note on the answer gate added after recording.

Data on screen: OpenFEMA disaster declarations (public US federal data; not endorsed by FEMA), SEC EDGAR XBRL frames and submissions (US government work; queried live through Zetaris, never redistributed), NOAA GHCN-Daily (CC0-1.0; cite NOAA NCEI) and the company_dns SIC list (Apache-2.0), all read through Zetaris.

Narration: a synthetic text-to-speech voice. No face, no human voice, no music.
